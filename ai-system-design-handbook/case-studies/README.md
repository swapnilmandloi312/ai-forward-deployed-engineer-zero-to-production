# Worked system-design cases

Every case below is a fictional design exercise, not a claim about a deployed client system. Volumes, costs, thresholds, and latency budgets are assumptions to challenge. Each includes a task, architecture, data contract, failure analysis, evaluation, and an extension exercise.

| Case | Main learning | Starting point |
|---|---|---|
| [Support knowledge assistant](01-support-assistant.md) | Permission-aware RAG and source freshness | Chapters 10–13 |
| [Invoice operations](02-invoice-operations.md) | Structured extraction, approval, idempotent writes | Chapters 4, 15–17 |
| [Marketing analytics assistant](03-marketing-analytics.md) | Exact metrics, data contracts, and grounded explanations | Chapters 2, 18, 23 |
| [Lead research workbench](04-lead-research.md) | Provenance, uncertainty, and human-reviewed outreach | Chapters 10, 14, 19 |
| [Healthcare operations copilot](05-healthcare-operations.md) | Sensitive evidence, segmentation, and reviewed recommendations | Chapters 13, 18–19 |
| [Coding assistant](06-coding-assistant.md) | Sandboxed tools, evidence, and change validation | Chapters 14–16, 20 |
| [Appointment voice assistant](07-voice-assistant.md) | Turn-taking, action state, and entity verification | Chapters 15, 20, 24 |

For interview practice, spend 40 minutes solving a case before reading the worked design. Use [the answer framework](../interview/answer-framework.md), then score yourself with [the rubric](../interview/rubric.md).
