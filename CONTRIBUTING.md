# Contributing

Contributions should make the repository more accurate, testable, or useful in a real deployment.

## Good contributions

- a correction linked to an authoritative source;
- a sanitized incident lesson converted into a test or runbook step;
- a small realistic dataset with documented provenance and license;
- an evaluation method with a reproducible example;
- a field playbook improved through actual use;
- accessibility, clarity, or broken-link fixes.

## Pull request checklist

- [ ] One focused change with a clear reason
- [ ] No customer, employer, personal, secret, or regulated data
- [ ] External claims and resources cite primary/official sources when possible
- [ ] New links resolve and internal paths use relative links
- [ ] Examples label assumptions, targets, and measured results distinctly
- [ ] The contribution is original or its license permits inclusion
- [ ] Any code or workflow includes setup, test, failure, and rollback notes

Open an issue before a large curriculum reorganization. By contributing, you agree that your contribution is licensed under the repository's MIT License.
